## §0. How to read this document

This is the definitive inventory of what BruteX **already has** that an options-strategy engine would consume, extend, or must build fresh. It merges six independent read-only repo surveys (lake · Greeks · executors · engine core · results/cascade · data quality), each of which verified every claim by reading the cited file at the cited line. Nothing here proposes activation; it maps substrate.

**Verdict vocabulary (normalized for the master matrix):**

| Verdict | Meaning | Absorbs the source sections' vocabularies |
|---|---|---|
| **VERBATIM** | An options-strategy engine consumes it unchanged (as code or as input data) | VERBATIM · REUSE-AS-IS · AGNOSTIC · EXISTS |
| **EXTEND** | Additive change under the component's own documented extension law (optional columns, appended enum members, new grid axes, recalibrated thresholds, ported gates) | EXTEND · REUSE-EXTEND · REUSE-WITH-EXTENSION · AGNOSTIC-WITH-SEMANTIC-DEBT · PARTIAL |
| **NEW-NEEDED** | No substrate exists — a new component (sometimes a SIBLING mirroring an existing shape, sometimes new sourced DATA) is required | NEW-NEEDED · SIBLING · COUPLED · NEW |
| **LEAVE** | Exists but is deliberately NOT a foundation — do not build on it | (one row only: the legacy `options/` tree) |
| **(GATED)** flag | Any change here is operator-gated DEC/ADR territory by the code's own text | GATED |

Where a component is VERBATIM at one granularity and NEW-NEEDED at another (e.g. per-leg vs netted), the verdict column carries the split and the notes say which half is which. The per-subsystem sections (§2–§7) carry the full evidence; the matrix is the index.

- Model: **Black-76 on forward F with discount `e^(−rT)`** (`mod.rs:8-15`). **The forward is built Python-side from spot**: `forward = float(spot) * math.exp(rate.rate * t_years)` (`greeks_enrich.py:1063`) — `F = S·e^{rT}` under the stamped `q = 0` assumption (`greeks_enrich.py:21-22`); general contract documented at `options/greeks.py:168-170`; "no exp is ever computed in Rust that Python didn't already compute" (`greeks_enrich.py:955-959`).

- Kernel constants (`mod.rs:92-115`; mirrored `options/greeks.py:66-79`): `T_FLOOR_YEARS = 600 s`, `IV_CLAMP_MIN/MAX = 0.001/5.0` (boundary never reported as "the IV"), `DELTA_ADMISSION_FLOOR = 0.02`, `VEGA_ADMISSION_FLOOR = 1e-6`.

### §5.5 The trade sim — what a "trial" is, fills, exits, performance envelope

**What a trial is:** one strategy mask evaluated over one tuple's bar window. Stage-1A builds a per-bar condition bitset (`brutex/engine/stage1a.py:1-13`); the Stage-2 supermask kernel turns a mask into a per-bar entry-signal stream; the walker "consumes that bool-per-bar entry stream plus the CandleBar feed and walks them bar-by-bar into round-trip `ClosedTrade` objects" (`brutex/engine/trade_sim.py:1-11`). Signal-only spot: "no slippage, no brokerage, no STT and money stays in int64 paisa end-to-end" (`:13-24`). O(1)/bar push, deterministic, no RNG (`:84-95`).

### §6.2 Ranking (`brutex/ranking/`)

## §7. Subsystem: data-quality guarantees — what a CE/PE 1-minute bar actually enjoys vs spot

**One-paragraph answer (preserved).** CE/PE 1-minute data shares the *write-boundary* guarantees with spot almost completely (same parse, same bar container, same `ParquetBarSink`/`ParquetWriter` with 2dp HALF_UP snap, keep-first dedup, calendar-aware session filter, future-bar drop, durable window ledger with bounded settles, raw-payload integrity hashes, partition flocks, atomic writes). It shares the *scan/heal* layer (dup/foreign/price-sanity findings on the `bars/…/FNO/` tree; the legacy `options/` tree has its own dup/foreign/overlap heal). Where CE/PE falls sharply behind spot is the *read boundary* and *completeness semantics*: the engine read-boundary guards (positivity-raise + bad-tick screen at `arrow_table_to_bars`) and the prebuild read gates (`make_lake_read_1m` price-sanity + ts-range + bad-tick) never touch CE/PE in production (engine spot-only; options prebuild retired), the executor's own lake reader applies **no** price-sanity or outlier screen (dedup only — the executor's per-trade rejects are the compensating guard), the ×4 bad-tick screen is *explicitly declared invalid for option premia* wherever options are screened (only the insane-row arm runs), completeness for options is deliberately weak (zero-today-bars abstains; interior-gap/truncation demotion is spot-INDEX-only; partial-window watch excludes CE/PE), and **no per-expiry strike-coverage / chain-completeness census exists anywhere** (verified by search). A future options-strategy engine inherits exactly this asymmetry.
