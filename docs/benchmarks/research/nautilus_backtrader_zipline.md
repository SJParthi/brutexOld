## 2. Backtrader (mementum/backtrader)

1. **Architecture** — "Live Trading and backtesting platform written in Python"; repo is "100.0% Python" (no compiled core); event-driven bar-by-bar Cerebro loop. Supports "Python >= 3.2", pypy/pypy3. VERIFIED(https://github.com/mementum/backtrader).
2. **Raw speed** — Known slow vs vectorized engines. Cited comparisons: vectorbt maintainer discussion — vectorbt "~1000x faster than backtrader" on a pairs-trading example with same results (SEC/VERIFIED-source-exists: https://github.com/polakowo/vectorbt/discussions/209; also #632 "difference between backtesting time for vectorbt and backtrader"). Blog benchmark claim: "VectorBT Pro … 167x faster than Backtrader on 100M tick datasets" (SEC — search snippet, appeared via bullalert/pineify-class blog; treat cautiously). Greyhound Analytics: "Backtrader is not designed for absolutely blistering speeds, rather it attempts to be easy to use" (SEC: https://greyhoundanalytics.com/blog/vectorbt-vs-backtrader/ — 403 on direct fetch, quoted via search). No official numbers from backtrader itself — VERIFIED-absence (README has no perf claims).
3. **Scale ceiling** — `cerebro.optstrategy(Strategy, param=iterable)` grid optimization with multiprocessing: "maxcpus" controls cores (default None = all cores; multicore on by default); `optdatas=True`/`optreturn=True` give "roughly 32%" speed improvement. VERIFIED(search snippets citing https://www.backtrader.com/docu/optimization-improvements/ + https://www.backtrader.com/blog/posts/2015-07-23-multicore-optimization/multicore-optimization/). Ceiling: each combo is a full Python event-loop run → thousands-to-tens-of-thousands of combos practical; millions/billions computationally infeasible (inference from the ~1000x-slower-than-vectorized evidence; no counterexample found).
4. **Statistical rigor** — Ships Analyzers: "TimeReturn, Sharpe Ratio, SQN" VERIFIED(https://github.com/mementum/backtrader). No DSR/CPCV/SPA/PBO anywhere in docs/feature list — VERIFIED-absence-of-mention.
5. **Data handling** — Multiple data feeds, "Integrated Resampling and Replaying" VERIFIED(GitHub README). No point-in-time database, no data-integrity/NaN quarantine layer documented — UNVERIFIED-absence. Look-ahead: bar-by-bar `next()` discipline only; no instrumented barrier — UNVERIFIED-absence.
6. **Fill realism** — Broker sim with "Flexible definition of commission schemes" (`setcommission`) VERIFIED(GitHub README); slippage via `slip_perc` (percentage) / `slip_fixed` (fixed) — VERIFIED(search snippets of backtrader docs). Volume-fill limits exist (fillers) — UNVERIFIED this session. No worst-case (bar-adverse-extreme) fill mode documented — UNVERIFIED-absence.
7. **Reproducibility** — Deterministic given same inputs (single-threaded loop), but NO run-identity hashing / content-addressed artifacts — UNVERIFIED-absence (nothing in docs/README).
8. **Crash resilience / automation** — No checkpoint/resume, no scheduler, no vendor rate-limit machinery documented; live feeds for IB/VisualChart/Oanda exist (VERIFIED GitHub README) but are dated. UNVERIFIED-absence for resilience features.
9. **Multi-asset breadth** — Anything you can feed as bars (equities/futures/FX/crypto via CSV/pandas); live brokers: Interactive Brokers, Visual Chart, Oanda. VERIFIED(GitHub README).
10. **License / cost** — GPL-3.0 (repo) / "GNU General Public License v3 or later (GPLv3+)" (PyPI). Free. VERIFIED(https://github.com/mementum/backtrader, https://pypi.org/project/backtrader/).
11. **Maturity** — 22.5k stars / 5.2k forks VERIFIED(https://github.com/mementum/backtrader). Last PyPI release 1.9.78.123 on 2023-04-19 VERIFIED(https://pypi.org/project/backtrader/) → effectively dormant ~3 years (inference from release date; community forks like backtrader2 exist — UNVERIFIED). ## 3. Zipline / zipline-reloaded (quantopian/zipline → stefan-jansen/zipline-reloaded)

1. **Architecture** — "Zipline is a Pythonic event-driven system for backtesting, developed and used as the backtesting and live-trading engine by crowd-sourced investment fund Quantopian." Python + pandas (>=2.0; NumPy 2.0 compatible; Python >=3.9) with C/Cython extensions (extensions UNVERIFIED this session). VERIFIED(https://github.com/stefan-jansen/zipline-reloaded).
2. **Raw speed** — No official numbers. Blog-class comparisons place it mid-pack: slower than vectorized (vectorbt), comparable-class to backtrader (SEC: medium "Battle-Tested Backtesters" https://medium.com/@trading.dude/battle-tested-backtesters-comparing-vectorbt-zipline-and-backtrader-for-financial-strategy-dee33d33a9e0 — 403 on fetch, not quotable). UNVERIFIED — no citable number captured.
3. **Scale ceiling** — No built-in parameter-sweep optimizer; grid search = user loop over `run_algorithm` (each a full simulation). Pipeline API "optimizes computations over the entire backtest period rather than tackling each event separately" (cross-sectional factor compute, not a combo sweep). VERIFIED-pipeline(https://stefan-jansen.github.io/machine-learning-for-trading/08_ml4t_workflow/04_ml4t_workflow_with_zipline/ via search). Millions/billions of combos: no.
4. **Statistical rigor** — Zipline itself: none of DSR/CPCV/SPA/PBO — VERIFIED-absence-of-mention (API docs searches). Ecosystem: **pyfolio-reloaded** = "performance and risk analysis of financial portfolios… tear sheets… risk tear sheet to analyze risk exposures to common factors" (VERIFIED via search: https://github.com/stefan-jansen/pyfolio-reloaded, https://pyfolio.ml4trading.io/); **alphalens-reloaded** = "performance analysis of predictive (alpha) stock factors" — returns/IC/turnover/grouped analysis tear sheets (VERIFIED: https://github.com/stefan-jansen/alphalens-reloaded, https://alphalens.ml4trading.io/). These are DESCRIPTIVE analytics — NOT multiplicity-corrected overfitting controls (no DSR/CPCV/SPA/PBO in their feature lists — VERIFIED-absence-of-mention).
5. **Data handling** — Genuine strength: "Zipline imposes structure… to ensure data quality by eliminating look-ahead bias, and it provides current and historical point-in-time data that avoids look-ahead bias"; "Returned data is adjusted for splits, dividends, and mergers as of the current simulation time"; data bundles + trading-calendars (exchange hours/holidays). VERIFIED(search snippets citing https://stefan-jansen.github.io/machine-learning-for-trading/08_ml4t_workflow/04_ml4t_workflow_with_zipline/ + zipline docs). **Bundle rot VERIFIED**: default Quandl WIKI bundle dead — "Quandl data feed update: WIKI stock prices — NO LONGER UPDATING as of April 11, 2018" (https://github.com/quantopian/zipline/issues/2145); "Quandl datasource for default bundle broken" (https://github.com/quantopian/zipline/issues/2603); "no free stock price data feeds available that can replace WIKI" (issue thread summary). Users must build custom bundles (recurring issues in stefan-jansen/zipline-reloaded #72, #99, #183).
6. **Fill realism** — `VolumeShareSlippage(volume_limit=0.025, price_impact=0.1)`: "models slippage as a quadratic function of percentage of historical volume"; volume_limit default 2.5% of bar volume per bar; price_impact scaling coefficient default 0.1. Also FixedSlippage / FixedBasisPointsSlippage; commissions PerShare/PerTrade/PerDollar. VERIFIED(search snippets citing https://zipline.ml4trading.io/api-reference.html + https://zipline.ml4trading.io/appendix.html; FixedSlippage/FixedBasisPoints + PerTrade/PerDollar specifics from docs pages surfaced in search — direct fetch 403, so parameter names beyond VolumeShareSlippage/PerShare = SEC-level). Volume-participation modeling is a realism strength (partial fills across bars). No worst-case-adverse fill mode — UNVERIFIED-absence.
7. **Reproducibility** — Deterministic sim given a fixed bundle ingestion; NO content-hashed run identity / bit-exact artifact machinery documented — UNVERIFIED-absence.
8. **Crash resilience / automation** — No checkpoint/resume, no scheduled zero-touch pipeline, no vendor rate-limit governor (bundle ingest is a one-shot CLI `zipline ingest -b quandl`). VERIFIED-ingest-CLI(https://github.com/stefan-jansen/zipline-reloaded); resilience features: UNVERIFIED-absence.
9. **Multi-asset breadth** — US-equity-centric (equities + futures support from Quantopian era); calendars for many exchanges via trading-calendars. Crypto/FX not first-class. Partially VERIFIED (calendars claim via ml4trading page); breadth limits = consensus/SEC.
10. **License / cost** — Apache-2.0 (zipline-reloaded). Free. VERIFIED(https://github.com/stefan-jansen/zipline-reloaded).
11. **Maturity** — Original quantopian/zipline: 20k stars, last release 1.4.1 on 2020-10-05, NOT formally GitHub-archived (no archive banner — nuance vs the brief's "ARCHIVED" assumption) but abandoned since Quantopian's late-2020 shutdown; README warns "we may not attend to your pull request, issue, or direct mention in months, or even years." VERIFIED(https://github.com/quantopian/zipline). zipline-reloaded: fork by Stefan Jansen ("forked from quantopian/zipline"), 1.8k stars / 310 forks, latest release 3.1.1 on 2025-07-23. One-maintainer bus-factor risk (inference).

## BruteX-relevant contrasts (for coordinator; analysis, not sourced claims)
- NONE of the three ships DSR/CPCV/SPA/PBO overfitting controls (verified absence of mention for all three) — BruteX's Stage-3/4 cascade + DSR is a differentiator.
- NONE documents a worst-case adverse-extreme fill law (Nautilus = probabilistic one-tick slippage / book-walk; Zipline = volume-share quadratic impact; Backtrader = perc/fixed slippage) — BruteX DEC-FILL-WORST-CASE-ONLY-001 is strictly more pessimistic.

- Zipline's point-in-time adjustment engine + trading calendars is the one genuine data-integrity strength among the three; its bundle ecosystem is verifiably rotted post-Quandl-WIKI (2018) / post-Quantopian (2020).
