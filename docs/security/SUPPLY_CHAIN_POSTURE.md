## 1. SBOM status

**Before this audit: no SBOM existed anywhere in the repo or CI** (grep for
`sbom|cyclonedx|spdx` across `.github/workflows/` had zero generation steps;
`docs/security/` did not exist).

**Now:**

- The three CycloneDX files above are checked in as a point-in-time snapshot.
- `.github/workflows/sbom.yml` (new, this audit) regenerates them on every
  push to `main`, on PRs touching dependency manifests, and on release, and
  uploads them as a CI artifact (90-day retention). It is deliberately
  **non-blocking** — it is not part of the `CI OK (aggregate gate)` required
  check, so a generation failure cannot wedge auto-merge.

**Honest caveats:**

- Python has **no lockfile** (`pyproject.toml` ranges only, by the
  DEC-P0-012 "always latest" policy; no `requirements*.txt`/`uv.lock`
  anywhere). The Python SBOM therefore describes *one resolution on one
  day*, not a pinned build. Two installs a week apart can differ. A
  committed lockfile (e.g. `uv.lock`) is the prerequisite for a stable,
  diff-able Python SBOM — that is a deps-workstream / operator decision,
  not made here.
- The Rust SBOMs exclude dev-dependencies (criterion, proptest, …) because
  `cargo-cyclonedx` describes the shipped artifact. The **license** sweep in
  `license-inventory.md` does include them (`cargo metadata` sees all 71 /
  143 resolved packages per crate).
- The two cargo-fuzz harness crates (`rust/*/fuzz`) have their own lockfiles
  and are not covered by these SBOMs; they are never distributed.

## 2. License posture

### The project's own license — finding L-1 (needs operator action)

- `pyproject.toml:7` → `license = { text = "Proprietary" }`; both
  `Cargo.toml`s → `license = "Proprietary"`.
- **There is no `LICENSE` file at the repo root** (verified:
  `find -maxdepth 1 -iname 'license*'` → empty), yet the repo is **public**
  (DEC-CI-FORK-PR-HARDEN-001, MIGRATION.md #1180, hardened "the PUBLIC
  repo's fork-PR attack surface"). A public repo with no license text is
  "all rights reserved" by default — which matches the proprietary intent
  but leaves the terms implicit. Adding a short proprietary-terms `LICENSE`
  file makes the position explicit and stops GitHub's license detector
  reporting "no license". This is an operator decision (repo root is outside
  this workstream's allowed paths).

### Third-party licenses — verdict: CLEAN for proprietary use

Full table in `license-inventory.md`. Summary of the automated flag sweep:

- **Python (137 third-party packages): zero strong-copyleft (no GPL/AGPL),
  zero sole-license LGPL, zero unknown/missing.** Distribution: MIT ×62,
  Apache-2.0 ×~29, BSD ×~29, plus PSF, ISC, Zlib, CC0.
- **Rust (145 unique third-party crate versions across both crates,
  dev/build deps included): zero strong-copyleft, zero sole-license LGPL,
  zero unknown/missing.** Overwhelmingly `MIT OR Apache-2.0`.
- Items a reviewer should know about (none is a blocker):
  - **MPL-2.0** (weak, *file-level* copyleft): `certifi`, `hypothesis`
    (dev-only), `pathspec`, `tqdm` (dual MPL-2.0 AND MIT). Using them
    unmodified carries no source-sharing obligation for BruteX's own code;
    only modifications *to those packages' own files* would have to be
    published. Compatible with a proprietary codebase.
  - **`lmdb` → OLDAP-2.8** (OpenLDAP Public License 2.8): a permissive,
    BSD-style license — not copyleft, fine for proprietary use.
  - **`r-efi` (Rust, transitive) → `MIT OR Apache-2.0 OR
    LGPL-2.1-or-later`**: LGPL appears only as one *choice* in an OR
    expression — MIT can be (and is deemed) elected. The two `cargo deny
    check licenses` configs (`rust/*/deny.toml`) already police this in CI.
  - `regex` → `Apache-2.0 AND CNRI-Python`, `numpy` → a compound of five
    permissive licenses: notice-only obligations.
- **Obligations that DO exist:** most permissive licenses (MIT/BSD/Apache)
  require preserving copyright + license notices **when distributing**.
  BruteX today distributes nothing (no PyPI publishing, no released
  binaries — see §3), so no obligation is currently triggered. If wheels or
  binaries are ever shipped, bundle a THIRD-PARTY-NOTICES file (the SBOMs +
  inventory here are the input for generating one).
- Rust license enforcement is already **continuous**: `cargo deny check
  licenses` runs in `security-audit.yml`. Python has **no equivalent CI
  license gate** — `pip-licenses` is in the dev extras but nothing runs it
  in CI (remediation item R-5).

## 3. SLSA posture (Build track, SLSA v1.0)

### What is actually released

`release.yml` runs only `googleapis/release-please-action@v5`: it opens a
version-bump PR and, once merged, creates the git tag + GitHub Release.
**No build artifacts are produced or published anywhere** — no PyPI upload,
no wheel/sdist attached to releases, no container images (verified: the only
`maturin` usage in workflows is `maturin develop` inside test/bench jobs).
Releases are source-only (GitHub's auto-generated tag archives).

### Current level: **SLSA Build L0**

There are no released build artifacts, and the source archives GitHub
generates carry no provenance/attestation. Nothing signs or attests
anything. That is L0 by definition — but note the *exposure* is also low:
consumers run from source they clone themselves.

### Source/dependency hygiene that already exists (better than L0 suggests)

| Control | State | Evidence |
|---|---|---|
| CI on every push + required aggregate gate | ✅ | `ci.yml` (`CI OK (aggregate gate)`), auto-merge refuses non-green (CLAUDE.md §2 Rule 13) |
| Fork-PR privilege hardening | ✅ | DEC-CI-FORK-PR-HARDEN-001 (#1180): author allowlist / live `author_association` trust gate; privileged jobs never check out PR-controlled refs; redteam pin suite |
| Branch protection | 🟡 server-side setup is an **owner task** (exact click-path in ledger #1176, per CLAUDE.md not yet claimed done); a daily **drift detector** (`branch-protection-drift.yml`) compares live rules to a checked-in snapshot and fails loudly if the rule is missing |
| Commit signing | 🟡 the last 20 commits on this branch all carry signatures (`git log --format=%G?` → `E` for each = signature present, key not verifiable in this environment — consistent with GitHub web-flow signing of squash-merges). Tag signing: not verified |
| Dependency update automation | ✅ Dependabot (`pip` + `cargo` + `github-actions` ecosystems) + `renovate.json` |
| Vulnerability scanning | ✅ `security-audit.yml` (pip-audit --strict, safety, cargo-audit --deny warnings, cargo-deny advisories/sources/licenses), CodeQL + Trivy + typos in `ci.yml`, secret scanning (`gitleaks.yml`, this audit), `safety.yml` (cargo-careful + ASan) |
| Lockfiles | 🟡 Rust: `Cargo.lock` checked in for both crates. Python: **none** — non-reproducible environment builds |
| GitHub Actions pinning | ❌ **0 of ~153 `uses:` references are SHA-pinned** (all mutable tags: `@v7`, `@v2`, `@v0.36.0`, …). A hijacked action tag executes with repo write tokens in some workflows |
| PR dependency review | 🟡 none existed; `sbom.yml` (this audit) adds `actions/dependency-review-action` on PRs, advisory (not in the required gate) |
| SECURITY.md / disclosure policy | ❌ absent (checked repo-wide) |
| Self-hosted runners | ⚠️ `bench-m4pro.yml` / `verify-m4pro.yml` run on a self-hosted M4 Pro — acceptable for benches, but any future *release* build must run on hosted runners or provenance claims are weakened |

### Path to higher levels (concrete, in effort order)

1. **L1 (provenance exists):** when artifacts are first published (e.g.
   maturin-built wheels), build them in a hosted-runner workflow and emit
   provenance with `actions/attest-build-provenance` (one step +
   `attestations: write` permission).
2. **L2 (signed provenance on a hosted platform):** the same GitHub
   attestations mechanism on GitHub-hosted runners satisfies the
   signed-provenance requirement; verify with `gh attestation verify`.
3. **L3 (hardened builds):** adopt the `slsa-framework/slsa-github-generator`
   reusable workflows for the release path. Only worth it once artifacts
   are actually distributed to third parties.

## 5. Reproduction commands

```bash
# Python SBOM (needs uv; resolves fresh — see the lockfile caveat in §1)
uv venv --python 3.12 /tmp/sbomenv
uv pip install --python /tmp/sbomenv/bin/python -e ".[data,ui,optimize,groww,token-broker,dev]"
uvx --from cyclonedx-bom cyclonedx-py environment --pyproject pyproject.toml \
    --sv 1.6 --of JSON --output-reproducible -o docs/security/sbom-python.cdx.json /tmp/sbomenv/bin/python

# Python licenses
uv pip install --python /tmp/sbomenv/bin/python pip-licenses
/tmp/sbomenv/bin/python -m piplicenses --format=json

# Rust SBOMs (cargo install --locked cargo-cyclonedx)
cd rust/trading-core && cargo cyclonedx -q --format json --spec-version 1.5 \
    --describe crate --all-features --target all -a
cd rust/fno-math && cargo cyclonedx -q --format json --spec-version 1.5 \
    --describe crate --all-features --target all -a

# Rust licenses (no install needed)
cargo metadata --format-version 1 --locked | python3 -c \
  "import json,sys; [print(p['name'],p['version'],p.get('license')) for p in json.load(sys.stdin)['packages']]"
```
