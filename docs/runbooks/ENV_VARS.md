# BruteX Environment Variables — Operator Reference

> **Last updated:** auto-generated by `scripts/ops/print_env_schema.py`

>
> ```bash
> python scripts/ops/print_env_schema.py > docs/runbooks/ENV_VARS.md

Every `BRUTEX_*` env var the engine reads, grouped by subsystem.
Set these in your shell, in `~/.brutex/env`, or in your systemd /
launchd unit before running `brutex monitor`, `brutex doctor`,
`brutex dashboard`, or any ingest command.

**Strict-decoder pattern (DEC-M4PRO-ABSOLUTE-001):** every boolean env
var requires the literal string `"true"` (case-insensitive, trimmed)
to activate. Any other value (`"1"`, `"yes"`, `"True!"`) explicitly
returns False.

## Quick smoke test

After setting env vars:

```bash
# 1. Verify the monitor sees them
brutex monitor --ticks 1 --poll-interval 0.01

# 2. Verify Telegram if enabled
python scripts/ops/test_telegram.py
```

If either fails, re-check the env-var name (case-sensitive, no
typos).
