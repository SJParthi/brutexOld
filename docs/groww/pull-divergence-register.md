# Groww Pull Divergence Register

**Audit target:** `origin/main` @ `2594df18e6e81cbb66548c6151aba1af7c9d1a5c` (fetched 2026-07-02).
Upstream verifier passes were pinned at `0a982935` / `909f79f`; every load-bearing citation used below was
**spot-rechecked at `2594df18`** where marked ✓. The sandbox has **no Groww credentials and no vendor
network** — every claim about *live vendor behavior* that is not repo-documented is marked **UNVERIFIED**
(Golden Rule #1/#10). Nothing here was fixed; this is a read-only register.

**Why this register exists:** the operator's real Groww pull has failed on his Mac for two weeks while
sandbox tests stayed green. Every sandbox test of the live pull runs against fakes. The rows below are the
places reality can diverge from the fakes, ranked by how likely each is to *be* the two-week mystery —
i.e. severity × silence.

**Column key**
- *Verification*: **CONFIRMED** = independently re-verified line-by-line at origin/main by a verifier pass
  (and spot-rechecked here where ✓); **PLAUSIBLE** = audited with citations but not independently re-verified;
  **UNVERIFIED** = only the Mac / the live vendor can tell.
- *Loud/Silent*: SILENT-skip (nothing happens, no signal), SILENT-wrong-data (wrong bytes land / wrong verdict
  shown), LOUD-vague (an error fires but doesn't name the cause), LOUD-misleading (an error fires and names the
  **wrong** cause/fix).
