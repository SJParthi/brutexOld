# ADR-0006 — Stage-2.5 Wald-SPRT early-stop: design + DECISION BLOCK

- **Status:** BLOCKED (design accepted; implementation gated on 5 must-prove items)
- **Decision ID:** DEC-SPRT-DESIGN-BLOCK-001
- **Date:** 2026-06-08
- **Method:** 4-agent hostile design review (CLAUDE.md Golden Rule #9) — a design
  architect + a hostile statistical/correctness reviewer, both reading the real
  code with `file:line` citations.

---

## Context

`docs/TRACK1_BACKTEST_SPEC.md` §"Stage 2.5" (`:351-356`) calls for a Wald-SPRT
"Bayesian early-stop" that kills a hopeless trial mid-flight to skip ~61% of full
backtests. This ADR records the **outcome of the mandatory pre-implementation
review**: the feature is **NOT safe to build as currently specified**, and is
**blocked** pending five must-prove items. The review *prevented* shipping a
subtly results-changing, non-deterministic optimization.

## Decision

**Do NOT implement Stage-2.5 SPRT until the five blockers below are resolved.**
When unblocked, build the **pure intra-backtest Layer-A design** (below) behind an
**explicit opt-in flag, default OFF**, with the A/B oracle gating every sweep —
**never** as a silent default.

---

## The five BLOCKERS (each independently disqualifying)

### B1 — The spec contradicts itself on what "Stage 2.5" *is* (Golden Rule #2 violated)
Two canonical repo docs specify **two different algorithms** on two different
statistical units:

| Axis | `TRACK1_BACKTEST_SPEC.md:351-356` | `TRACK1_OPTIMIZATIONS.md §2` + `docs/phases/phase_2_5_bayesian_early_stop.md` |
|------|-----------------------------------|------------------------------------------------------------------------------|
| Stopping unit | **≥50 closed trades** (intra-backtest) | **≥50,000 param-trials** (inter-backtest, `MIN_TRIALS=50_000`) |
| Accumulates | one combo's per-trade PnLs | the 95th-pct Sharpe across a combo's SL/TP grid |
| Action | CONTINUE / KILL | CONTINUE / PRUNE / PROMOTE |

These are not two views of one thing. **One algorithm must be locked with a
decision ID before code.** This ADR adopts the **spec's intra-backtest definition**
(cheaper, safer, deterministic, fits the existing `metrics_for_mask` seam).

### B2 — It is NOT correctness-neutral; it changes the ranked leaderboard
The kill criterion is **Sharpe-percentile**, but the leaderboard is an **8-term
composite** weighting Risk-Efficiency / Calmar / Profit-Factor
(`brutex/ranking/__init__.py:301-318`). A below-median-Sharpe combo can still rank
on a non-Sharpe term. Worse, the composite is computed on **z-scores across the
*surviving* population** (`ranking/__init__.py:285-291`) and the Deflated-Sharpe
gate deflates against `N = len(candidates)` (`ranking/overfit.py:221-242`) — so
**pruning combos changes the z-scores and the DSR threshold of the combos it
keeps.** Unlike the *exact* `min_hits` prefilter (a mask with <30 hits *cannot*
produce 30 trades — `sweep_driver.py:264-272`), the SPRT invariant is
**probabilistic** (a bounded β=0.10 false-kill rate), **not exact**. It must NOT
be sold as "provably identical leaderboard."

### B3 — Determinism risk (Golden Rule #4/#7)
The `OPTIMIZATIONS.md` design uses a shared `DashMap` + Rayon batch boundaries, so
kill decisions depend on **thread scheduling** → non-reproducible → breaks the
audit-replay oracle. **Mitigation (adopted):** the Layer-A design makes the kill a
**pure deterministic function** of a combo's own trade stream + an injected
threshold (no `DashMap`, no clock, no RNG, no cross-trial state) — which restores
determinism. Any future Rust port must preserve this and add a byte-identical
Python↔Rust parity golden test.

### B4 — The p95 threshold must track the real `top_k`, not a hardcoded 95
The "killed combos never rank" argument only holds when the kill percentile
corresponds to the leaderboard's actual top-K tail. `cfg.top_k`
(`sweep_run.py:732`) is operator-set and may exceed the 5% tail. The threshold
must be derived as `(1 − top_k/pool)·100`-th percentile, not a constant 95.

### B5 — The Rust kernel is not wired into the production sweep, and the SLA lacks an honest worst case
The production persisted sweep runs the **Python** `metrics_for_mask` loop
(`sweep_run.py:715-730`); `ResidentTradeSim.simulate_masks`
(`brutex/engine/rust_trade_sim.py:148`) **exists but is not called** by
`run_persisted_sweep`. So the real perf win requires wiring Rust *first*. And the
"~61% reduction" headline (`OPTIMIZATIONS.md:18`) has **no worst-case row**: if no
combo crosses the threshold before its floor, the sweep does 100% of the work
**plus** SPRT overhead — a net slowdown. Per Golden Rule #10 the honest SLA band
floor is "0% pruned + overhead", not 45%.

## The accepted design (build this when unblocked) — pure intra-backtest Layer-A

A single new pure module `brutex/engine/early_stop.py` (sibling of `trade_sim.py`),
**opt-in, default OFF**, reusing existing numerics (CLAUDE.md §11 COMMON):

- `SprtConfig` (frozen, validated): `alpha=0.05`, `beta=0.10`, `min_trades=50`,
  `kill_posterior=0.10`.
- Module constants from α/β: `A_LOWER = ln(β/(1−α)) ≈ −2.251`,
  `B_UPPER = ln((1−β)/α) ≈ 2.890` (Wald bounds; formulas in code comments per
  spec `:356`).
- `RunningSharpe` — Welford online (`n`, `mean`, `m2`), O(1) per trade, reusing the
  exact recurrence in `brutex/metrics/compute.py:134-145`.
- **`sprt_decision(stat, *, p95_threshold, tau_low, cfg) -> Decision`** — the PURE
  core: `CONTINUE` while `n < min_trades`, else `KILL` iff
  `probabilistic_sharpe_ratio(SR̂, benchmark=p95_threshold, n, skew, kurtosis) <
  kill_posterior` (reusing `brutex/metrics/deflated_sharpe.py:125-174` verbatim —
  it *is* "Pr(true Sharpe > benchmark)"), with the LLR Wald bound as a
  cross-check. **Zero I/O / clock / RNG** → trivially 100% line+branch +
  deterministic. `p95_threshold` + `tau_low` are **injected**, never computed
  inside.
- `simulate_trades_with_early_stop(...)` — thin wrapper around `TradeSimWalker`
  (`trade_sim.py:189,315`) that feeds each `ClosedTrade` into `RunningSharpe`,
  calls `sprt_decision`, and stops pushing bars on `KILL`, returning
  `(trades, KillInfo | None)`. A killed combo is **excluded from ranking but
  marked evaluated+seen** and emits a `STAGE_2_5_KILL` hash-chained audit line —
  it never reaches `rank_combos`, so its absence is the entire effect.

### Test plan (7 types + audit-replay)
1. **Unit** — every `sprt_decision` branch + `SprtConfig` validation + the Wald
   constants, at 100% line+branch (the pure function makes this achievable).
2. **Property (P-25/P-26 for Stage-2.5)** — monotone hopelessness; determinism
   (same stream + same injected p95 → same decision, bit-for-bit); look-ahead
   preserved (killing can't change a trade that closed before the kill bar).
3. **Golden** — early-stop OFF is **byte-identical** to today's
   `run_persisted_sweep` output (the opt-in default-OFF guarantee).
4. **Bench** — the trial-reduction proof: `Σ bars_walked_SPRT / Σ baseline` drops
   materially on a seeded dud-heavy fixture **AND** top-K is unchanged on it; plus
   the O(1)-per-trade ratio gate.
5. **Stress** — sustained sweep with early-stop ON; no drift, bounded memory.
6. **Integration (A/B oracle)** — 100 real Stage-1B combos, frozen seed: baseline
   top-10 vs early-stop top-10 → **top-3 recall = 100%, top-10 ≥ 95%**. This is
   the empirical backstop for the *probabilistic* invariant.
7. **Mutation** — `mutmut` / `cargo-mutants` ≥ 85% on the new module + Rust port.

Plus **audit-replay**: `STAGE_2_5_KILL` events reproduce byte-identically.

## Consequences

- **Positive:** the mandatory review caught a results-changing, non-deterministic
  feature before any code; the spec contradiction (B1) is now visible and tracked.
- **Negative / honest envelope (Golden Rule #10):** Stage-2.5 stays unbuilt, so the
  "~61% faster / single overnight" SLA is **not yet achievable** — the engine
  backtests every Stage-2 survivor to completion. This ADR does not change that;
  it prevents a *false* speedup that would corrupt the leaderboard.

## Follow-ups (the unblock checklist)
1. Lock ONE algorithm (B1) with a decision ID; reconcile `BACKTEST_SPEC.md` ↔
   `OPTIMIZATIONS.md` ↔ `phase_2_5_*.md`.
2. Tie the kill percentile to the real `top_k` fraction (B4).
3. Compute the composite/DSR over the FULL candidate pool (not just survivors) so
   pruning can't mutate survivor scores (B2), OR accept + document the
   probabilistic envelope + gate on the A/B oracle.
4. Make the decision a pure, order-independent function (B3) + add the Rust↔Python
   parity golden test.
5. Wire `ResidentTradeSim.simulate_masks` into `run_persisted_sweep` and publish
   the honest no-prune worst-case SLA (B5).

- **2026-06-08 — DEC-SPRT-AB-ORACLE-001:** the **A/B oracle**
  (`tests/integration/test_stage2_5_ab_oracle.py`) empirically pins down **B2**
  and **B4** against the real 8-term `rank_combos`:
  - **B4 (characterized):** the literal spec threshold (the pool's

    sweep is the remaining B4 code (still blocked with B5).
  - **B2 (empirically guarded):** with the `top_k`-tracked bar, early-stop kills
    only clear duds and **preserves the leaderboard** (top-3 recall 100%, top-10
    recall ≥ 95%) on a deterministic 30-combo fixture.
  - **Residual B2 risk (honest, unchanged):** this is a fixture spot-check, NOT a
    proof over the 33B-trial space, and does NOT cover the worst-case combo that
    is low-Sharpe but high on a non-Sharpe composite term (Risk-Efficiency /
    Calmar / PF). Until that case is bounded — and B5 (Rust production wiring +
    honest worst-case SLA) lands — early-stop stays **inert / unwired**.
- **2026-06-08 — DEC-SPRT-B2-RESIDUAL-001:** the residual-B2 worst case is
  **CONFIRMED REAL, not theoretical** (`tests/integration/test_stage2_5_b2_residual.py`).
  An adversarial pool containing **low-Sharpe / high-Risk-Efficiency** combos
  shows that even the `top_k`-tracked early-stop **drops gate-passing full-sweep
  top-10 combos** — because those combos rank via the composite's *non-Sharpe*
  terms (Risk-Efficiency / Calmar / PF) yet are killed by the *Sharpe-based*
  criterion. Verified: with seed 0, **4 of the baseline top-10 are adversarial
  combos (Sharpe 0.09–0.32) that early-stop kills**, changing the leaderboard.
  **Decision:** early-stop **CANNOT be wired with a Sharpe-only kill.** Before any
  B4-wiring/B5, the kill must be made **composite-aware** (e.g., never prune a
  combo that ranks top-K on the *full* composite, or rank over the full pool and
  prune only the bottom tail). **B4-wiring + B5 remain BLOCKED.** The inert core,
  the B1 spec-lock, and the A/B oracle stand; the unsafe step is now proven unsafe
  with a guardrail regression test (honest, no-illusion — Golden Rule #10).

## FINAL VERDICT (feasibility review, 2026-06-08) — DEC-SPRT-INFEASIBLE-001

A composite-aware kill was investigated as the only path to safely wiring
early-stop. **Verdict: a *provably* leaderboard-preserving SPRT early-stop is
INFEASIBLE** — feasible only under assumptions that void the speedup. The
obstruction is structural, not a choice of kill statistic:

1. **No sound mid-flight bound for the non-Sharpe terms.** The leaderboard ranks
   on 8 full-backtest aggregates (`brutex/ranking/__init__.py:301-318`). None
   admit a sound lower/upper bound from a 50-trade prefix — `max_drawdown_pct`
   (`brutex/metrics/compute.py:262-307`), Calmar, and **Risk-Efficiency**
   (`ranking/__init__.py:165-177`, the proven attack term) can be dominated by
   trades that have not happened yet. The only available signal is the
   *probabilistic* PSR on Sharpe — already disproven unsafe (DEC-SPRT-B2-RESIDUAL-001).
2. **The score is relative + pool-coupled.** Every term is z-scored across the
   *surviving* pool (`ranking/__init__.py:180-193,285-291`) and the Deflated-Sharpe
   gate deflates against `N` + pool variance `V` (`ranking/overfit.py:204-242`).
   Pruning ANY combo perturbs every survivor's z-score AND the DSR bar. The only
   perturbation-free normalization computes the composite over the FULL pool —
   which needs each killed combo's *true* final metrics, i.e. the exact backtest
   early-stop exists to skip. **Closed circle.**

So a composite-aware kill is either **unsafe** (probabilistic bounds) or
**non-accelerating** (exact bounds require the full backtest). There is no
safe-and-fast middle. This mirrors the only prune already proven safe — the
**exact** Stage-1B `min_hits` prefilter (`brutex/engine/sweep_driver.py:264-272`),
safe precisely because it is exact, not probabilistic.

### Decision
- **Stage-2.5 SPRT early-stop is ABANDONED as a sweep accelerator** (not merely
  blocked). The kill criterion cannot be made both safe and accelerating.
- The merged artifacts STAY as documented building blocks + guardrails: the inert
  `brutex/engine/early_stop.py` core (#511), the A/B oracle (#515), and the
  residual-B2 proof (#516). They are not wired and must not be.
- **B4-wiring and B5 are CLOSED** (was BLOCKED) — there is nothing safe to wire.

### Redirect (leaderboard-safe speedups that already exist)
1. **Exact Stage-1B coarse prefilter** (`sweep_driver.py:264-272`,
   DEC-STAGE1B-WIRE-001) — the correct, exact, deterministic, leaderboard-preserving
   shape of the SPRT idea. Tightening it (exact gate-derived bounds) is the
   productive direction.
2. **Phase-3.5 Metal GPU offload** (`docs/TRACK1_OPTIMIZATIONS.md §3`) — bit-exact
   numerical-parity + audit-replay byte-identity gated, so it accelerates without
   touching the ranking math (leaderboard-safe by construction).

### Honest envelope (Golden Rule #10)
The "~61% reduction / single overnight" SLA built on Stage-2.5
(`TRACK1_OPTIMIZATIONS.md §1`) is **NOT safely achievable and should be retired
from the SLA table.** The achievable leaderboard-safe speedup is the Stage-1B
prefilter (in tree) + the bit-exact GPU path.
