Sort basis: the "Rank by" metric, descending (server-ranked) — differs from the one-click Top-100, which ranks by its artifact preset (default min_dd_first: smallest max-drawdown first).
Year/quarter/month buckets: IST exit-date attribution, per-trade-close equity. Per-period max-DD is segmented within the period — a year's DD is NOT the max of its months' and understates boundary-spanning drawdowns; the row's max-drawdown column remains the authoritative risk figure. Half-year DD is not stored — shown as —. Yr-gate chips are DISPLAY verdicts at current default thresholds derived from stored buckets; the rank-time gate config of each run is recorded in the sweep audit chain. Year-gating ADDS a calendar-aligned constraint on top of DSR/CPCV/WFO — it does NOT remove curve-fitting (at defaults it passes ~50% of pure noise over 7 years). — = no stored data / not judged. DSR (tuple-N) is the persisted per-tuple Deflated Sharpe — deflated against ONE grid cell's rank-time candidate count, an inflating under-count, so it is never shown unlabeled; DSR @ search N is the Stage-4 cascade's own filter-#2 figure at its recorded trial population (hover the cell for N + source; a "pool"-sourced figure shares the under-count and pairs with the ~ provisional badge). The Min trades / Min PF / Min DSR / Max |DD| floors are OPERATOR controls over a board already min-trades-gated at rank time — Min DSR floors the tuple-N column. A † on the rank marks a row failing a persisted hard door on serve-time re-check (a legacy or non-gated store row) — marked, never dropped. B&H bench % is the STORED buy-&-hold return of the combo's results-depth run (the R27 baseline artifact) over the window in the tooltip — served verbatim, never recomputed; a combo no depth run captured reads —. It is a same-window reference, NOT the combo's own %return (the row's P&L is absolute paisa, not %).
